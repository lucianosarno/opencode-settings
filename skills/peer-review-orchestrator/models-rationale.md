**Primary sources (for fallback rationale):**

- Deterministic `llm_selection` ranking summary: `cursor` × `capability_weighted`

## What we optimize for

Peer review is **long structured writing, cross-doc consistency, critique, and conceptual modeling**.

Weights in the shortlist track (proposers / critics):

1. **Cursor billing** cost (API/task USD + CTR where applicable)
2. **Capability-weighted** value: `((1+quality)**3) / est_cost_cursor`
3. **Cursor Task allow-list** (hard at dispatch — unmapped fallback rows are skipped)
4. **Provider diversity** in the fallback file (one seat per provider; no Luna+Terra+Sol stack)
5. **Provider + family diversity at dispatch** (hard): one Task family per slot **and**
   one vendor per peer review — Luna and Sol cannot share a roster; same for Sonnet+Fable
6. **Roster sizing**: `min_slots` floor, then tau (vs leader) + rho (vs previous) only on
   seats beyond the floor — see `roster_sizing` in skill `config/settings.json`

**Phase 5 leader (skill-side rule):** pure `quality` from
`ranking_calculation_latest.json`, among the participant families — cost is **not** in
the denominator. Configured by `leader_selection` in skill settings (does not require a
new shortlist artifact from `llms_peer_review`).

## Fallback lineup (`models.yaml`)

Auto-built from summary_rank order among models that are (a) in the cursor capability_weighted
top-N track and (b) `available_in_cursor`, keeping **unique providers**. Effort variants and
extra OpenAI/Anthropic lines collapse to the first hit for that provider.

When Task-mapped, the YAML value is the Task slug; otherwise the `llm_code` (e.g. Gemini / GLM /
Kimi). The orchestrator only dispatches allow-listed Task slugs and skips the rest.

Residual seats (if ranking did not cover every Cursor-available provider) come from other
`available_in_cursor` codes with unused providers (`cursor_available_residual` in the JSON report).

## When Luna / Sol / Terra appear in the shortlist

Only the **best-ranked OpenAI** Task family wins a seat for that application; Sol/Terra/GPT-5.5
after that are skipped as `duplicate_provider:OpenAI`. Same rule for Anthropic (Fable/Opus/Sonnet).
The global fallback already keeps one seat per provider; dispatch applies the same constraint
on top of the shortlist so a review never ends up with two vendors duplicated.

## Optional diversity swap

Review-local overrides still win:

- Set seats in `{REVIEW_ROOT}/peer_review.models.yaml`.

Do **not** hand-edit the global `models.yaml` — it is overwritten on the next ranking refresh.
Update this rationale only when the sync rules or Task map change.
